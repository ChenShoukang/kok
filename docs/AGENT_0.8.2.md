# v0.8.2 · 可核对的 Agent 与 MCP

[English](AGENT_0.8.2.en.md) · [使用指南](GUIDE.md) · [验证记录](VALIDATION_0.8.2.md)

**源码开发版，尚未发布。** 已发布下载仍是 v0.8.1 Preview。本轮把任务计划、完成核对、请求追踪和本地 MCP 工具接到现有资料库、操作历史与活动中心；保留 C# / WebView2 实现，没有引入大型 Agent 框架。

## 使用中的变化

1. 给 Agent 选定资料、提出要求。多步骤任务可显示一份简短计划，执行中保留勾选、展开状态和草稿。
2. 本地搜索与阅读自动进行；修改继续显示前后预览，由你执行或跳过。MCP 外部工具每次都需要确认。
3. 任务结束前模型调用 `finish_task`，说明完成、部分完成或需要信息，并引用实际工具回执。未核对就耗尽请求时显示“上限已到”，不冒充完成。
4. 点击“执行追踪”，查看每次请求的状态、HTTP 码、耗时、token、估算费用与重试事件；可导出诊断 JSON。

主机检查回执是否存在、成功、在当前任务中，以及相关本地资料是否已修改或撤销。**它不能独立证明模型的语义结论正确。** “工具依据已核对”代表检查了执行依据；不使用工具的回答只标为“模型已自检”。未补救的失败、跳过或撤销不能用于宣称完整成功。完成后撤销、或再次查看时发现本地依据变化，会清除核对并标记“核对已失效”；补充要求会将旧计划显示为失效，不能继续显示旧的完成勾选。

“需要补充信息”的任务若仍有预算，可直接在输入框补充并继续同一个任务，保留资料范围与原请求 / 费用上限。选定资料按选择顺序传给模型，避免“第一份”变成最近导入的那份。模型还会收到剩余请求提示，以及合并计划更新与结果核对的指导；这减少多余轮次，不能保证每个模型都能在上限内完成。

纯文字构思等推理步骤可在计划中标为“模型判断”，无需为了凑执行证据而调用无关工具；这类步骤不被冒充为实际工具验证。

计划不是强制复制会话或自动生成子 Agent。完整事件加密留在本机；发给模型的是范围内的证据和有界上下文。显式交接沿用已有引用机制。

## 失败与用量

| 情况 | 行为 |
| --- | --- |
| 连接失败、超时、HTTP 408 / 425 / 429 / 5xx | 模型请求最多额外重试 2 次，退避并加入小幅抖动；每次均计入请求和费用上限 |
| `Retry-After` 超过 30 秒 | 停下并允许之后手动处理，不无视限流，也不无限等待 |
| 认证、额度、上下文、普通 400 / 422 参数错误 | 不盲目重试；显示分类后的原因 |
| 明确拒绝 `tools` / `tool_choice` / `functions` 参数 | 自动协议下只切换一次兼容 JSON；不把任意 400 / 422 都当成不支持工具 |
| 本地只读工具暂时失败 | 保存失败状态，可显式续跑；没有为所有模块自动重试 |
| MCP 工具名或参数不正确 | 未执行整轮调用，最多两轮修复，与内置工具共用请求预算；修正后仍需审核 |
| MCP 返回 `isError` | 将错误正文作为不可信工具结果保留并回传模型；可在本地查看，不当作成功或自动重复执行 |
| 外部调用结果不确定、进程中断时仍在执行 | 不自动重放；先检查外部结果，再交接或开始新任务 |

没有服务商用量时，按保守输入 / 输出上界估算；这不是实际账单。耗尽预算的失败不会提供一个立即再次超限的“继续”按钮。

## 连接 MCP

入口在 **Agent 空白页 → 外部工具 MCP**，也在 **设置 → 功能 → 外部工具 MCP**。

1. 先自行安装可信的 MCP 服务及它要求的运行时。
2. 添加服务，填写本地 `.exe` 完整路径、参数（每行一项）和所需环境变量（每行 `KEY=value`），确认信任后连接。例如 Node 服务选择已安装的 `node.exe`，第一行参数填写本地服务的 `.js` 路径。这里不自动安装包或运行 `npx`。
3. 展开参数结构，勾选允许 Agent 使用的工具，保存授权。
4. Agent 先检查已批准工具，再提出具体调用。确认卡片显示服务器 ID、工具名和完整参数；你点击执行后才发送 `tools/call`。外部调用不加入“执行所选”，每项单独执行；界面和原生入口都阻止批量批准。

MCP 程序以**当前 Windows 账户权限**运行，可访问资料库以外的文件和网络。这里没有系统沙箱；资料范围不约束外部服务。服务器声称“只读”也不会免确认，外部副作用不提供假撤销。使用自己的可信服务并审核参数。

- 配置（包含环境变量）整体使用当前 Windows 账户 DPAPI 加密；界面与模型清单不回显环境值。外部程序本身可访问授予它的环境，亦可能在结果里返回敏感数据。
- 不继承 kok 进程的任意 API 环境变量，只保留必要系统变量和你显式填写的值。
- 重启后不自动启动 MCP 服务；手动连接。授权绑定可执行文件哈希、参数、环境配置和工具定义；实际调用前再次核对工具定义。**解释器参数指向的脚本正文、脚本依赖尚未哈希**，修改这些内容未必触发重新授权，必须自行信任并管理服务。
- 纯净模式、私密文件夹、停用相关模块及退出会关闭连接。Windows Job Object 管理服务及其子进程的退出；这是生命周期管理，不是隔离权限。
- 最多 12 个服务、每个服务 64 个工具；参数与结果有长度 / 深度上限，正文结果按节选传给模型。图片、远程资源和服务器请求不会自动加载或授权。

当前为 **stdio tools 客户端子集**：支持 2026-07-28 的 `server/discover` / 每请求元数据，以及 2025-11-25、2025-06-18、2025-03-26、2024-11-05 的旧初始化方式。仅支持有界的基本 JSON Schema（对象、数组、基础类型、必填、枚举、范围等）；`$ref`、组合断言等不支持的结构会禁用该工具。没有声称完整实现 JSON Schema 2020-12 / 全套 MCP。

Streamable HTTP、OAuth、资源 / 提示词、sampling、输入交互和订阅不在本版范围。MCP 不是自动安装任意插件，也不是开放 shell 的默认许可。

## 诊断与评测

本地任务事件继续包含用于恢复的完整内容，并加密存储。**诊断导出与原始事件不同**：仅有时间、状态、随机 ID、请求指标、计划状态与数量；排除目标、文件名、提示词、正文、参数、服务商错误原文、密钥及模型自检文字。

工具卡片与执行追踪可按需打开“本地工具结果”，包含外部错误正文；该正文不会因此加入诊断导出。费用列仅在配置输入 / 输出单价后显示估算，未配置显示 `—`，不是免费或真实账单。

默认测试使用本地模拟模型和真实 stdio 子进程，不消耗 API。另提供六项可选真实模型评测：事实与未知信息、计划后确认写入、拒绝修改、提示注入、版本对比、缺失信息。评测最多每项 4 次模型请求，需显式选择并提供凭据文件；没有运行就不报通过。详见[验证与命令](VALIDATION_0.8.2.md)。
