# Agent 与作品共用一份内容

本轮先完成文档和 PPT 的真实创建、修改、预览、确认与撤销，再调整平面视觉。Agent、我的作品、资料库继续保持三个独立入口：Agent 执行任务，作品承载编辑，资料库提供观看、收听和阅读。

## 参考与取舍

研究来源为 [JimLiu/baoyu-design](https://github.com/JimLiu/baoyu-design/tree/6759e358eb88d83986c753b0fc60c84e4aabdb3a)，固定提交 `6759e358eb88d83986c753b0fc60c84e4aabdb3a`。其 README 的作品目录、逐页编辑、Agent 与用户交替修改、局部反馈和历史恢复，支持 kok 围绕同一份作品工作的方向。进一步参考 [Slidev 的布局系统](https://github.com/slidevjs/slidev/tree/main/packages/client/layouts) 中封面、章节和双栏的职责划分。实际 PPTX 编辑沿用本项目的原生 OpenXML 处理和已内置的 PptxGenJS。

baoyu-design 的 [NOTICE](https://github.com/JimLiu/baoyu-design/blob/6759e358eb88d83986c753b0fc60c84e4aabdb3a/NOTICE.md) 区分维护者的 MIT 本地工具与未授予 MIT 许可的 Anthropic 编辑器、字体和技能文本。本次没有复制这些编辑器、字体、提示词或编译包，没有内置外部服务器、插件或新账户系统。工作流参照与独立实现写在这里，Pi 的实际代码改编另见 [PI_AGENT_UI.md](PI_AGENT_UI.md) 和许可文件。

## 本轮交付

- **文档正文**：`read_document` 返回带续读位置的精确原文窗口；`replace_document_text` 只修改一个唯一片段。正文与资料笔记分别处理，保留格式、其他章节和文件身份。支持 MD、TXT 和 DOCX。
- **PPT 创建**：`create_presentation` 生成实际可编辑 PPTX。支持 paper、midnight、violet 三种风格，以及 cover、content、two_columns、section、quote 五种版式。详细解释和来源可写进演讲备注，页数包含封面。
- **PPT 局部修改**：`read_presentation` 按页读取原文、元素 ID、坐标与备注；`edit_presentation` 支持文字片段替换、备注修改、页面重排、替换版式、插入和删除。每个修改批次按顺序执行并作为一个操作撤销。
- **原件保护**：导入的 PPTX 可由 `copy_presentation` 先完整复制到作品目录，再编辑。定向文字修改直接修改 OOXML 包，未涉及的页面、媒体、图表和母版文件保留。修改某一页的版式会重建该页的可见基础内容。
- **共同预览**：聊天旁可查看实际文件；PPT 提案也可在写入前逐页预览。翻页、切换大纲、刷新和打开编辑器均在本机处理，不请求模型。
- **恢复与冲突**：准备提案时记录原文状态，确认时重新核对；手动改动或草稿会阻止旧提案覆盖。已完成修改有持久回执与加密文件历史，重开后可以撤销，停止或恢复任务不会自动重放写入。
- **节省上下文**：文档使用窗口和唯一片段替换，PPT 使用页范围和元素 ID；读取时省略图片数据并限制文字总量。PPT 工作流指引仅在相关任务中附加，避免向所有问题重复发送长设计说明。

## 边界

PPT 的基础预览和排版编辑不等于 Office 的完整渲染。复杂动画、SmartArt、表格和图表不保证在本机预览中还原；文字定向修改保留未触及的原包内容。基础编辑器对含复杂元素的文件保留草稿，并在导出基础副本前说明损失范围。

本轮没有实现整套网页画布、数据仪表盘、多人协作、音乐生成或视频生成。以后扩展这些作品类型时，可以复用同一流程：给出任务要求，围绕实际作品预览，选择具体位置反馈，局部修改，记录版本。应由实际可用的工具决定界面入口，避免只有模板或对话而没有产物。

## 验证方式

原生测试验证实际 PPTX/MD/TXT/DOCX 文件、文件身份、修改范围、原包保留、版本回执、冲突与撤销；桌面测试通过回环模型夹具验证完整交互。验证不会发送真实模型付费请求，也不把模型输出质量当成已由夹具证明的事实。
