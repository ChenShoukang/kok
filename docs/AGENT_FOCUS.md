# Agent 聚焦：资料与结果优先

[项目首页](../README.md) · [文档目录](README.md) · [30 项任务评测基线](AGENT_TASK_EVAL.md)

本页说明这一轮 Agent 改版围绕的两个目标：**让第一次使用的人少做选择**，以及**让系统少发送无关内容、少重复执行**。改版没有推翻既有的混合检索、重复读取复用、上下文压缩、任务记录、审批与撤销；它把已有能力重新组织成一条更容易理解的完成路径：选择资料 → 说明结果 → 本地可判定的请求立即回答 → 需要模型时只读取相关片段 → 结束时交付可打开的成果。

## 1. 首页围绕资料与结果

默认首屏只保留四类内容：已选资料与「添加资料」、输入要求、根据当前资料给出的 2–4 个建议操作、开始/停止与必要的确认。技能、请求上限、上下文档位、协议、资料范围和任务方式收进默认折叠的「高级设置」，原有控件与设置项保持不变。

- 选中资料后，范围自动按「所选资料」生效，并在输入框上方用一行显示当前范围；选「指定分类」仍是显式操作。
- 建议操作按所选资料变化（摘要、待办、对比、讲解视频重点、整理图片说明等），点击只填入输入框，不代替用户发送。
- 会话与任务记录仍在首屏可达，恢复、停止、审批和撤销的入口不变。

## 2. 本地任务分流：能确定就先本地回答

新增原生只读动作 `agentLocalPlan`（`src/AgentLocalTasks.cs`）。它在用户发出请求前，对「统计这个分类里的视频数量」「列出最近三天的视频」「有哪些分类，各自多少份资料」「标了 #设计 的资料有哪些」这类**显式动词 + 显式约束**的只读请求做本地解析，直接返回统计或清单，**零模型请求、零网络、零写入**。

- 支持数量统计、列表/筛选、分类概览、标签概览、文件类型分布；约束可组合（类型、扩展名、分类、标签、收藏、时间窗、大小阈值）。
- 带「总结 / 分析 / 建议 / 整理 / 生成 / 制作 / 比较 / 删除」等生成或写入语意的请求一律不本地处理，继续交给模型。
- 解析保守：缺少明确约束、范围含糊、无读取动词时返回未命中，由模型路径接手；界面在这种情况下不提示错误，行为与之前一致。
- 该动作只要求普通资料库权限，不要求 AI 与网络，因此**没有配置 API 密钥也可以使用本地分流**；纯净模式与私密文件夹沿用原有本地化拒绝逻辑。
- 本地结果以卡片呈现，标注「本地完成 · 未调用模型」，可打开命中的资料，也可用「用 AI 深入分析」把原请求交给模型继续。

## 3. 片段级读取：证据分散也能到达

- `search_library` 现在对同一份长文件可返回最多 3 个命中片段（默认总数 12，上限 24），每个片段带页码 / 章节 / 字幕时间与序号，引用按片段编号；此前每份文件只保留首个片段、每段约 240 字。知识面板和 MCP 的检索仍保持每文件一条，不受影响。
- `read_items` 返回每份来源的读取覆盖（实际读入字符 / 可提取字符、是否采样），并在正文后追加一条有界摘要，例如「Coverage: 2/2 sources; a.md full, b.pdf sampled 3200/48000 chars」。全文总结类任务可以据此判断是否需要补读，而不是默认已经覆盖全文。
- 每轮携带的文件目录不再只是「最近 20/40/80 份」：在范围内先给用户所选/最近资料，再用本地词面检索补入与目标相关的候选，配额仍受原有档位约束；不调用模型或 embedding。目录在任务开始时计算一次并在整条任务中保持不变。
- 仍然可复用已提取正文、字幕、OCR 与索引结果；检索与读取不改变原文件。

## 4. 缓存友好的消息构造

工具调用协议下，消息顺序调整为**稳定前缀 + 动态尾部**：

1. 系统规则（含资料范围与「仅讨论」限制）；
2. 本地资料目录与引用证据；
3. 用户选择的技能/指令；
4. 历史会话与已发生的工具轮次（追加式增长）；
5. 最后一条宿主状态消息：上下文检查点（如有）、任务指导与记忆、宿主回执索引。

此前每轮变化的回执索引插在历史之前，会让后续所有消息无法复用缓存；现在只有尾部状态消息变化，稳定的前缀更可能命中服务商的前缀缓存。JSON 兼容协议的构造未改。

## 5. 任务结束交付可打开的成果

任务结束后新增成果卡片：结果标题（新建的文档/演示文稿优先）、状态（已完成 / 部分完成 / 需要补充信息 / 已停止）、「使用 N 份资料 · M 处来源引用」，以及「打开文档」「查看来源」「继续修改」；成果保存在会话里，重开资料库后仍在。批量整理保留逐项修改前后预览与勾选执行，批量栏先汇总将改动的内容再确认。中断的任务仍可从已完成步骤继续，不重跑整段。

## 6. 先测量再谈节省

同轮新增 30 项固定任务样本、离线校验器与可选的（opt-in）真实模型评测入口，见 [30 项任务评测基线](AGENT_TASK_EVAL.md)。评测在**同一批样本**上同时记录正确性、成果可打开、引用可回溯、输入/输出 token、费用、耗时、重试、重复读取和首次使用信号。本轮没有执行真实模型评测（没有授权的 API 预算与密钥），因此这里不给出任何节省比例。

## 验证

- 原生：**608 项检查通过**（基线 542 项 + 新增 45 项本地分流检查与 14 项片段检索 / 读取覆盖 / 目标目录 / 稳定消息前缀检查）。覆盖纯模式与私密文件夹拒绝、本地分流只读性、范围隔离、消息前缀字节级稳定等确定性路径。
- 桌面（最终构建、官方 9225 端口）：`agent-interactions`、`agent`、`agent-reliable`、`agent-runtime`、`agent-kernel`、`agent-platform`、`agent-quality`、`mcp`、`modules`、`features`、`interface-usage`、`app-modes`、`ui`、`flat-design` 通过；`library-services` 与 `i18n` 按新的短侧栏「更多」面板适配后复测通过。`agent-interactions` 覆盖首屏高级设置默认折叠、随所选资料变化的建议、批量摘要、成果卡片、本地卡片零模型请求与重载后保留、500–1280 px、中英文、零页面错误与零外部请求。
- 静态：`npm run check`（样式构建、语法、模块架构、语言目录、文档链接与版本契约）。
- 交付包：`dist/kok-0.9.8-win-x64.zip` 经解包、版本、SHA-256、源代码与运行文件指纹核对及独立资料库桌面复验；记录见 `test-output/package-*/archive.json`。
- 真实模型前后对比（用户授权，同批 30 项样本）：改造前 v0.9.5 包 100 次请求 / 566,586 输入 tokens，改造后 76 次请求 / 431,132 输入 tokens，即**请求 −24.0%、输入 token −23.9%、保守费用 −21.4%**，两轮均为 26/30 通过；节省几乎全部来自本地任务分流（8 项本地任务由 21 次请求变为 0），模型任务自身用量基本持平。4 项未达项、单轮随机性与完整用量见[验证记录](VALIDATION_0.9.8.md)与[评测基线](AGENT_TASK_EVAL.md)。

## 未纳入本轮

- 按任务裁剪工具组、简单结构化判断使用快速模型、失败后升级模型：仍按现有「权限 + 模块 + 允许工具」过滤执行，模型选择与工具组分层留待后续。
- 「登录即用」的托管服务（账号、计费与运维）：仍需要用户自行配置 AI 服务，本轮只做好本地分流与连接后的使用路径。
- 局部修改（例如只改第三页）仍由现有撤回保护与重新生成承担，尚无定向补丁机制。

## 边界

- 本地分流只覆盖可判定的只读请求；同义改写、需要理解内容的请求仍走模型。
- 片段检索仍是词面 / 本地 embedding 混合，没有重排器；「相关候选」按词面匹配补充，可能漏掉改述。
- 覆盖数字来自有界提取（正文上限 120k 字符 + 笔记 6k 字符），不是原始文件字节数；无法读取的来源只计入分母。
- 成果卡片的「引用」以本机读取结果返回的来源为准，不保证每个结论都被证据支持。
- 30 项评测的在线部分尚未运行，真实模型输出存在随机性，固定样本也不等于全部使用场景。
