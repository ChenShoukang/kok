## 完整使用路径

1. 在“我的作品”创建项目，填写目标和要求，加入三份资料；点击“继续创作”。
2. 请 Agent 根据资料写报告，检查读取来源与拟保存正文，确认后生成托管文档。
3. 在成果面板打开编辑器，手改一段并保存；保存前可检查逐行差异。
4. 选中第二节，点击“让 Agent 改这段”，补充要求后发送；查看替换内容，确认后修改同一份报告。
5. 请 Agent 将已有报告转为八页 PPT；查看页面方案后确认保存。
6. 重新打开软件，在同一项目新建会话，继续修改已有 PPT 的指定页。项目目标、要求、资料及已有成果由项目记录恢复。
7. 打开报告版本面板，选择已命名检查点，确认恢复；编辑器同步恢复后的正文和保存状态。
8. 导出报告为 DOCX、演示为 PPTX，选择新的保存位置。取消另存为不会创建导出文件。导出副本仍可重新导入阅读。

## 本轮补齐的续作边界

项目默认可操作范围同时包含近期成果和原始资料。近期成果优先，去重后最多 24 份；超出时需要通过“添加资料”明确选择本次要用的文件。手动选择文件或指定文件夹仍优先，不会因为项目有成果而擅自扩大范围。没有项目文件时保留既有范围行为。

同一任务等待补充信息后继续，原生会话按任务事件序号追加后续消息；不会因为任务曾经同步过就跳过新内容，也不会重复追加旧消息。已有分支成果节点保持可达。

## 验收方式与限制

`tests/creative-e2e.cjs` 使用真实 Windows WebView2、原生任务、文件写入、进程重启、另存为对话框及导出回读。本地模型夹具负责给出固定创作内容，以验证应用流程、审批、文件一致性和局部修改边界，不代表真实模型的写作或排版质量。重启模拟隔天继续，不修改系统时钟，也不声称做过跨日长时间运行测试。

报告恢复使用已有补偿式恢复机制；PPT 可编辑、续作与导出，本轮没有新增 PPT 版本可视化比较。原始三份资料保持不变；导航、恢复、导出不增加模型请求。发布包为本地 Preview ZIP，不代表已上传公开 Release。
