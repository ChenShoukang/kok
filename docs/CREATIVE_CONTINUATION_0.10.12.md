# 创作项目 P3：持续创作与命名检查点

[项目首页](../README.md) · [创作项目](CREATIVE_PROJECTS_0.10.10.md) · [版本与局部改稿](VERSIONS_0.10.11.md) · [验证记录](VALIDATION_0.10.12.md)

## 项目成果独立于聊天消息

项目成果取自原生 workspace 项目记录。切换到同一项目的其他会话、从早期消息分叉、压缩上下文或重新打开软件，项目已经登记的成果仍可从成果面板打开。面板重新读取实际文件，不把聊天中的提案当作已保存作品。

普通会话另有加密的成果索引，记录任务所创建或修改的托管文件 ID。成果索引不重放工具卡片，不执行旧操作，也不改变当前文档版本。普通会话的索引遵循选中的分支；项目成果则由项目记录管理。

同一任务等待补充信息后再次完成时，后续新增成果仍会登记到项目与会话中；重复完成回调不会重复建立关联。

分支树中可以识别成果节点。选择历史分支后重新打开会话，界面保留该分支，不会自动用最近一次已完成任务替换它。项目没有旧任务的新会话也会加载项目成果。

异步读取绑定当前会话和资料库边界；快速切换项目或会话时，迟到的读取不会覆盖当前界面。已移除、非托管及不支持预览的文件不作为可打开的成果展示。

## 命名检查点

在托管文档编辑器的“版本”面板中，可以为某个历史版本添加、修改或移除检查点名称，例如“第一稿”“提交前”。名称最多 64 个字符，保存在当前资料库独立的加密元数据文件中，重新打开软件仍可读取。

选择带名称的版本可以查看差异，恢复时沿用已有二次确认和补偿式恢复操作。恢复本身仍可撤销。历史列表仍限制为 100 条，在限额内优先保留已命名检查点，避免大量自动保存挤掉阶段稿。标签操作不修改正文，不创建模型请求，不启动 Agent 任务。

保存名称失败时保留原来的内存与磁盘状态；写入使用临时文件和原子替换，上一份元数据保留为备份。已有损坏标签文件可在后续命名时修复，原始字节留在备份中。

## 范围

本轮完成 P3 的成果持久化与命名检查点。文档版本面板继续面向 MD、TXT、DOCX；PPT 的版本可视化对比仍未接入。命名针对历史版本，当前版本是动态条目。审批、证据核对、撤销、私密文件夹和沙箱规则继续由现有原生机制处理。

P4 的“三份资料→报告→局部改稿→八页 PPT→换会话继续→恢复→导出”完整场景作为下一阶段验收，不在本轮宣称完成。
