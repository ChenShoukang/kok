# kok 资料库可视化规划

更新于 2026-11-26。基线为 v0.16.3 开发候选。本专题优先做**每个分类的拟物 Logo、统一视觉语言和流畅动效**，再将同一套设计用于电影、剧集、个人视频、文档专题、音乐和自建频道。实施顺序以 [v0.16 收尾清单](V016_COMPLETION_CHECKLIST.md)及[项目总规划](PROJECT_PLAN_0.14_TO_1.0.md)为基础。

## 当前实现

- 资料库的「我的分类」直接读取现有分类。新建分类后，可以从文件菜单归类，也可以在资料库首页把文件拖到分类标签。每个分类都有默认图标，点进分类后可预览并保存自己的图案和底色。
- 分类目录已用上米白底和八款拟物图标。详情页沿用原文件卡片和排序。返回目录时恢复滚动位置和键盘焦点，减少动态效果开启时直接切换。
- 图标设置随本地资料库和 .koklib 备份保存。下一批先迁移频道和专题的稳定身份，再支持分类改名、批量加入及一份素材进入多个频道。之后接电影、剧集和个人视频的数据视图。

## 用户打开资料库时看到什么

从现有的「资料库」进入。主体采用温和的米白底、深灰棕色文字和少量浅米色图标底板，拟物 Logo 保留物件材质与阴影。顶部保留全库搜索，下面是「视频」「文档」「音乐」「我的分类」四个入口，当前入口用短下划线和文字深浅标明。点入视频后才显示电影、剧集和个人视频。跨类型自建的旅行日记、课程资料可以从「我的分类」进入。

```text
资料库   [ 搜索文件、正文、频道、专辑或歌手 ]
视频   文档   音乐   我的分类

视频分类     [胶片盘]        [复古电视]      [随身相机]
               电影            电视剧          个人视频

打开电影     ← 返回视频
               [胶片盘]  电影
               电影内容列表
```

分类卡片主要显示 Logo 与名称，轻底板承托 Logo。界面分隔线集中在导航和需要扫读的列表。点开后，顶部入口保持可见，同一枚 Logo 出现在详情页标题旁。返回按钮直接说明目的地，例如「返回视频」，回到原卡片的焦点与浏览位置。切换顶部入口时直接进入对应的分类列表。

频道或专题的说明、成员和专辑或电影详情放到进入之后的页面。查看电影时优先显示海报，观看个人视频时优先看到画面，找音乐时优先看到专辑封面和歌手。每个视图都可以切回列表，便于扫文件名、筛选和批量整理。宽窗口展示多列，小窗口在减少列数的同时保留主要入口和足够的点击范围。

## 视频

| 入口 | 显示内容 | 主要操作 |
| --- | --- | --- |
| 电影 | 竖海报、片名、年份和继续观看进度 | 播放、编辑信息、换海报、加入一个或多个频道 |
| 剧集 | 剧集海报，进入后按季和集浏览。单集显示横向缩略图、集名、时长与进度 | 继续观看、修改季集号、补录缺失剧集、手工调整错分条目 |
| 个人视频 | 横向缩略图、拍摄或导入日期、时长 | 按日期浏览、选择封面帧、加入自建频道 |
| 我的频道 | 自建频道名、Logo、说明、置顶和手动排列 | 新建、批量添加、移除成员、修改 Logo 和调整顺序 |

- 本地文件名里的年份和 `S01E02` 等明显季集标记可用于给出整理建议。用户可以预览、逐条应用，或直接手动归类。识别有歧义时仍在「全部视频」可见。
- 将同一视频加入「旅行日记」与「待剪素材」后，两个频道打开的是同一资料。继续观看进度跟随资料，频道中的排序可以各自调整。
- 首批做手动频道。后续增加按类型、现有标签或日期筛选的自动频道，创建时预览匹配结果并保存筛选条件。
- 第一批支持本地上传海报、选取画面和设置片名。标题与年份的在线匹配作为单独入口，用户选中对应版本后再应用。文件夹里的海报和影片年份等组织方式可参考 Jellyfin。 [Jellyfin 电影](https://jellyfin.org/docs/general/server/media/movies/) · [Jellyfin 剧集](https://jellyfin.org/docs/general/server/media/shows/)

## 文档

文档沿用频道卡片的交互，在界面上叫「专题」。例如「摄影学习」「工作报告」「旅行资料」。每个专题可以有 Logo、封面和简介，能混合收录 PDF、DOCX、Markdown、PPT 与笔记，支持手动顺序、按最近更新和按标题浏览。跨原有分类整理一条阅读顺序，可参考 Komga 的阅读列表。 [Komga 阅读列表](https://komga.org/docs/guides/readlists/)

- 文档卡片显示标题、格式和最近阅读进度。PDF 优先用可读取的首页缩略图，普通文档用标题和格式生成封面，用户可换成自己的封面。首批复用现有预览链路。
- 专题内可以搜索正文，再从结果打开原页、章节或摘录。进度、笔记、批注及原文锚点继续使用现有资料身份。
- 可以手工把相关初稿和终稿关联起来。对已存在的 kok 文档修订复用版本查看能力。对从外部导入的不同文件，以用户确认的「当前版本」标记为准，保留各自原件和出处。
- 「用所选资料创作」复用现有 Agent 资料选择与作品流程。用户从专题指定素材后，可以做报告或演示，并回到专题看对应来源和成果。

## 音乐

kok 已有专辑网格、歌手列表、我的音频、文件标签与内嵌封面读取。这次以现有音乐页为基础，把专辑和歌手做成能稳定收藏、编辑和返回的页面。

| 入口 | 显示内容 | 主要操作 |
| --- | --- | --- |
| 专辑 | 方形封面、专辑名、专辑歌手、年份、曲目数 | 进入专辑、整张播放、换封面、编辑专辑信息 |
| 歌手 | 自定义头像或文字图标，专辑和参与演唱的曲目 | 查找歌手、播放作品、打开专辑 |
| 专辑详情 | 按碟号和曲号排的清单，单曲显示实际歌手、时长和格式 | 播放整张、从当前曲目继续、修正分组或顺序 |
| 播放列表与我的录音 | 自定义封面、名称和顺序，录音保留自己的浏览入口 | 将曲目加入多张列表，或查看个人录音和其他音频 |

- 导入时尽量读取内嵌歌手、专辑、专辑歌手、年份和曲号。加入碟号后按碟号、曲号排序，缺少顺序数据时按标题显示并可手工调整。
- 优先使用已有发行标识关联同一发行版本。无标识时用专辑名、专辑歌手与有效年份等信息提出分组。遇到不同歌手的同名专辑、同一歌手的重发版本、合辑或信息缺失时，支持手动拆分、合并与纠错。
- 一张合辑可以有多个曲目歌手和单独的专辑署名。歌手页同时列出以该歌手为专辑歌手的发行和参与演唱的单曲。
- 封面默认优先采用用户指定图，其次用同目录的专辑图、音频内嵌图，最后用占位图。用户确认封面后，重扫标签继续使用该封面。参考 Navidrome 的专辑署名、合辑和封面优先级。 [Navidrome 标签规则](https://www.navidrome.org/docs/usage/library/tagging/) · [Navidrome 封面解析](https://navidrome.org/docs/usage/library/artwork/)

## 分类 Logo 与封面

资料库分类入口优先展示 **Logo 和类别名**。每个现有分类、预置分类及新建分类都拥有一个可编辑的标识，详情页沿用同一个标识。具体作品仍有自己的电影海报、文档封面或音乐专辑封面。

### 第一套视觉方案

参考旧书装帧与摄影器材的质感。图形用同一方向的柔光、温和的阴影和低饱和颜色。用纸纹、哑光金属、磨砂玻璃和黑胶沟槽表达不同类别。每枚保留一个主物件和一个可辨识细节，实物轮廓从侧栏小尺寸一直延伸到分类首页。

| 分类 | Logo 造型 | 识别细节 |
| --- | --- | --- |
| 电影 | 黄铜胶片盘 | 圆盘孔位与一截底片 |
| 电视剧 | 墨绿色复古电视 | 圆角屏幕与调谐旋钮 |
| 个人视频 | 黑色随身相机 | 凸起镜头与取景窗 |
| 学习文档 | 布面书与纸页 | 书脊、页层和书签 |
| 工作资料 | 橄榄色档案夹 | 页签与纸质目录贴 |
| 音乐专辑 | 黑胶唱片和纸质唱片套 | 唱片沟槽和中心标签 |
| 歌手 | 小型录音室麦克风 | 网罩与短支架 |
| 自建频道 | 从同套实物图案选择 | 如旅行频道采用明信片和邮票，用户可以换物件与配色 |

独立制作侧栏简化图和卡片细节图。小尺寸用轮廓与一处细节，分类首页有空间时再显示纹理、材质和第二层物件。确认深浅主题下的可读性，并在灰度下验证类别能凭形状区分。统一图形的占位尺寸、留白、光源和视觉重心，分类名称继续显示在图旁。

### 自建分类与旧分类

1. 创建时从同一套图形中选择，配色从共用的调色板选取。离线可以完成选择、编辑与保存。
2. 旧分类第一次打开时，先按已有类别匹配同主题图形，信息不足时使用资料夹、书册或其他通用实物模板。保存后按分类稳定 ID 读取标识，改名后仍可识别原 Logo。
3. 用户可上传本地图片或选用资料中的图片，并预览卡片与侧栏两个尺寸。分类图与页头封面可各自保存。重新扫描资料时继续读取用户设定。

## 动效方案

动效表现一次明确操作的结果。悬停或键盘聚焦时，Logo 稍抬起，光影随物件一起移动。按下时快速回压。打开分类时，同一个 Logo 从卡片位置移到详情页标题旁，再显示内容。返回时保持原浏览位置，焦点回到刚打开的卡片。

| 动作 | 首版节奏 | 实现要点 |
| --- | --- | --- |
| 悬停与聚焦 | 约 150–180 毫秒，抬起 2–3 像素 | 仅当前 Logo 上有反馈，鼠标离开时平滑返回 |
| 按压 | 约 75–95 毫秒 | 轻微收缩，点击和键盘操作均可触发 |
| 打开与返回分类 | 打开约 260–300 毫秒，返回约 200–240 毫秒 | 只过渡选中 Logo 和相关内容。目标立即响应，动画可取消 |
| 筛选和拖拽整理 | 约 140–200 毫秒 | 保留下来的卡片短距离移动，及时接受下一个筛选、返回或拖拽 |
| 减少动态效果 | 引用系统和 kok 的动态偏好 | 直接切换位置和尺寸，选中、焦点与导航反馈完整保留 |

- 参考开源 Motion 的共享元素、基于 `transform` 的布局过渡和可中断的切换。kok 首选复用现有的 `ui/calm-motion.js`、`ui/motion-core.js` 与 Web Animations API。对无法平稳衔接的场景，再以本机 WebView2 的同页对比决定是否需要引入额外依赖。 [Motion 布局动画](https://motion.dev/docs/layout-animations) · [Motion 视图动画](https://motion.dev/docs/animate-view)
- 分类和位置发生变化时测量起点、终点各一次，再用 `transform` 和 `opacity` 动画。纹理、材质和大面积阴影预先绘制或保持静态。系统减少动态效果可参照 Animate.css 的适配。 [Animate.css 无障碍动效](https://github.com/animate-css/animate.css/blob/main/docsSource/sections/08-accessibility.md)
- 真机验收需覆盖快速连续切换、中途返回、键盘与触摸、深浅主题、减少动态效果，以及有大量分类时的滚动。分别检查 Logo 缓存冷、热两种状态，在同一台机器记录输入到首帧的延时和卡顿帧。计时数值作为首版设计目标，实际流畅度以 Windows/WebView2 测试记录为准。

## 资料组织、升级和存储

| 对象 | 保存什么 | 如何复用已有数据 |
| --- | --- | --- |
| 资料 | 现有文件 ID、位置、进度、笔记与预览状态 | 播放器、阅读器、索引、作品和 Agent 按同一 ID 查看 |
| 频道、专题、播放列表 | 稳定 ID、名称、域、说明、排序模式、置顶和 Logo 引用 | 组织位置可调整。同一资料加入多个集合时各自保存一条成员关系 |
| 剧集与季集 | 剧集身份、季号、集号与实际视频的关联 | 重扫与改名时保留已确认的关系。文件缺失时提供重连入口 |
| 专辑与歌手 | 稳定 ID、署名、发行或创作者信息、封面与曲目关系 | 导入时从现有字段提出分组，允许用户确认、拆分和合并 |
| 缩略图与自定义图 | 生成图的版本和缓存，自定义图的持久附件引用 | 按列表和详情页准备合适尺寸。自动缓存可重建，用户图片可随备份恢复 |

- 保留旧分类入口和现有分类、标签、收藏、播放与阅读进度。第一次使用新视图时可以把旧分类复制为专题或频道，再按需编辑。成员关系只引用文件。删除频道或移除成员时，确认界面描述对应的整理动作，原资料、标签和历史继续在资料库中可访问。
- C# 层复用现有 SQLite 和库对象存储，负责关系、图片文件以及可撤销的整理操作。用现有资料 ID 关联，保存成员、顺序和图片引用时保持事务一致。升级检查以旧库可打开、重复迁移结果一致、失败后旧数据可恢复为准。
- 区分手工设置与生成信息。修改文件、重新读取标签或重新分类后，用户已选的封面、归类和已确认身份继续生效。素材路径变化沿用资料重连机制。
- 便携导出与恢复需要扩展版本契约，让频道、专题、成员、手工顺序和用户自定义图片可以迁移。经迁移的资料 ID 映射要同时更新各处引用。旧包继续用已有流程恢复。自动生成缩略图可在新设备按需重新生成。
- JavaScript 界面复用卡片、列表、选择、分页和媒体预览。图片按当前显示尺寸加载，大量条目使用分页或延迟渲染。刚导入或未生成缩略图时先显示占位图，搜索和播放仍可操作。
- 继续使用现有 Agent 内核。基础导入、分类、分组、播放和封面编辑由本地功能直接完成。Agent 从 UI 选定的资料范围检索和创作，后续可给出归类建议，用户预览后应用。相关入口复用现有资料检索和打开原文流程。 [现有检索与恢复说明](LIBRARY_0.9.0.md)

## 可实施顺序与验收

| 批次 | 交付 | 完成后如何验证 |
| --- | --- | --- |
| 第一批 · 分类 Logo 和动效 | 完成首套分类 Logo、旧分类默认标识、自建分类模板、侧栏和卡片展示，以及按压、打开和返回动效 | 以电影、剧集、个人视频、学习文档、工作资料、专辑、歌手和自建频道为首套样本，核对小尺寸、深浅主题、快速切换和减少动态效果。改名及重启后仍可找到同一 Logo |
| 接续交付 · 可自建的资料库 | 频道、专题的通用编辑与列表，视频三种分类，批量添加成员、置顶和 Logo 编辑，文档首屏封面 | 把同一个个人视频加入「旅行日记」和「剪辑素材」。改两处顺序、换 Logo、重启。移除一个频道后，从另一个频道仍能打开该视频并继续观看 |
| 第二批 · 剧集与文档整理 | 剧集、季、集详情及标题建议，电影海报与信息编辑，文档专题搜索和定位 | 导入两部同名不同年的电影及两季有缺集的剧。核对年份、季集、播放位置，修正一条错分。把 PDF 和 DOCX 放入同一专题，搜索后打开实际原页，并从专题继续阅读 |
| 第三批 · 真实专辑和歌手页 | 读取并整理专辑身份，处理合辑与多碟，补齐换封面、歌手和真实播放列表 | 导入同名的两张专辑、一张多碟合辑和几首无标签曲目。确认各专辑能独立浏览，顺序正确，歌手页有参与曲目。换封面后重新读取标签并核对 |
| 第四批 · 整理提效 | 自动频道、本地批量归类、可选在线匹配、通常用到的跨资料创作入口 | 预览并撤销一次批量归类，离线重复基本操作。导出后在新库恢复频道、封面和成员顺序。用选定文档生成并重开可编辑 Word 或 PPT |

每批同步验收旧库升级、布局和保存恢复。用混合大库检查快速滚动、搜索和切换时的响应，用普通库和私密库分别验证资料、封面与集合的隔离。首次打开、查找指定资料和整理一批文件的步骤数与耗时，使用同一份样本在现有界面和新界面各跑一遍并记录。

第一批先把「分类 Logo → 点击打开 → 返回原位置」做成一条能连续用的流程。再接「新建视频频道 → 制作 Logo → 加入已有文件 → 再次打开继续观看」。文档专题复用创建与编辑流程。专辑视觉页已经存在，可在同一时期处理分组和封面问题，再做稳定的专辑身份和复杂音乐元数据。后续剪辑和创作可以直接选择已整理的素材。
