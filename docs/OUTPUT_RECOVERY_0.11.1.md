# v0.11.1：回答未完成时继续创作

[项目首页](../README.md) · [创作完整路径](CREATIVE_ACCEPTANCE_0.10.13.md) · [验证记录](VALIDATION_0.11.1.md)

## 面向第一次使用 Agent 的恢复体验

用户只需要提出目标、查看结果和确认修改。回答较长时，软件先在原请求与费用限制内自动调整，最多重试两次。报告、文章、文档等长内容创作会得到更合适的初始输出额度，不要求用户先理解模型参数。

如果仍未完成，结果卡片显示“回答未完成”和“分段继续”。点击后，输入框保留原目标并补入“本轮只完成第一部分、保留已有成果”的要求，当前资料选择继续保留；用户可以直接发送，也可以先调整。这一步不自动发请求、不新建任务。一般失败与达到请求上限后的“继续修改”也会带回原目标，避免只剩一句无法执行的“继续修改”。

## 修复原因

此前模型返回 `finish_reason=length` 时被归为输入上下文超限，可能触发无效的上下文压缩。现在使用独立的 `output_limit` 类型，在原生工具协议及 JSON 兼容协议中调整输出额度，保持目标和已读取的资料。

恢复必须重新生成完整响应。截断的 JSON、工具参数，甚至随 `length` 返回但看起来完整的工具调用，都不会成为可执行提案。只有重新生成、校验通过的完整修改才显示审批入口。之前已经确认并完成的操作不会因为重试而重新执行。

流式响应先接收最后一个文字增量和尾部用量，再报告输出上限，避免丢掉已收到的尾文或漏记消耗。重试仍经过原生请求次数与费用预检；单次输出最多 8,000 token，并受用户配置的输出预留限制。没有提高任务的请求次数、费用上限或审批权限。

## 验证边界

使用隔离资料库、真实 WebView2 与本机模型夹具，验证四份资料、输出截断、完整提案审批、失败后的分段草稿和重载。验证的是应用恢复流程与文件一致性，不代表所有服务都支持更长输出；服务自身上限仍可能导致需要分段完成。
