# kok v0.11.1 实用性复核

[用户帮助中心](help/index.md) · [公开版验收](https://github.com/ChenShoukang/kok/actions/runs/41975352619)

kok 最有价值的一条路径，是把已经在电脑里的资料变成**有出处、能继续改、可以交付的作品**。例如，把三份会议资料做成一份报告和一份可编辑 PPT，下次打开同一项目继续修改。资料库的阅读和播放本身也有独立价值，用户可以按自己的习惯使用。

这条创作路径已经能跑通。发布包验收覆盖了读取资料、修改原稿的指定段落、制作八页 PPT、重启后续作、恢复历史文档和导出回读。验收中的模型由本机夹具模拟，能说明流程和文件操作有效。普通用户能否自行找到入口、不同模型能否交出满意的作品，仍需单独验证。[端到端验收说明](CREATIVE_ACCEPTANCE_0.10.13.md) · [v0.11.1 验证范围](VALIDATION_0.11.1.md)

## 优先补齐的四件事

| 优先级 | 现在做到哪里 | 下一步和验收方式 |
| --- | --- | --- |
| **P0 · 第一次成功** | 示例资料、本地统计和阅读笔记模板都有各自的入口。第一次写报告或生成 PPT 还要配置服务、选资料并组织要求。 | 在首次使用时给出 **用示例试一次**。沿用现有本地统计或笔记模板，让用户先打开结果并在「我的作品」找回笔记。用户选「根据资料生成」时再引导配置服务。找 5 位没用过 Agent 的人试，目标是至少 4 位在 5 分钟内完成本地练习，无需旁人指路。 |
| **P1 · 找回并交付作品** | 创作项目保存目标、资料和成果，详情目前列出成果文件。作品页只展示近期 24 个项目，没有完整项目搜索入口。PPT 暂无文档式版本对比。 | 给项目补 **全部项目 / 搜索**，在成果旁显示保存状态和最近导出记录。优先给托管 PPT 做可命名、可恢复的阶段稿。验收时准备超过 24 个项目，重启后找到较早项目，核对交付版本与文件位置，恢复一份阶段稿再导出。 |
| **P1 · 来源、质量和费用可预期** | 已有来源引用、写入审批、任务用量和截断后的分段继续。自动化验收使用固定模型输出，当前版本的真实生成质量需另测。 | 把「资料 → 报告」和「报告 → PPT」做成可复用的短流程。发送前显示范围和请求上限，预览时让用户核对引用、关键数字、页数和文本溢出。用真实模型做小规模对照，记录首次可交付比例、人工改动次数、用量、耗时和失败后的续作成功率。 |
| **P2 · 换机后还能继续做** | `.koklib` 已支持校验和恢复到新库，带托管作品，也可选带普通原件。Agent 对话、任务、私密库和密钥各有不同的恢复边界。 | 先做一张导出前清单，展示会带走哪些作品、还需另备哪些内容。恢复后列出找不到的原件和可重新关联的位置。用两台 Windows 设备或两个独立环境验收，逐项核对报告、演示、笔记、摘录、项目和缺失原件。 |

实现依据包括[项目列表与成果界面](../ui/modules/works-page.mjs)、[托管文档的命名检查点](CREATIVE_CONTINUATION_0.10.12.md)、[回答恢复](OUTPUT_RECOVERY_0.11.1.md)和[便携资料库的范围](help/settings/data-backup.md)。表内的验收目标是建议，尚未做新手试用或当前版本的真实模型对照评测。

## 下一版的范围

如果只做一轮，我会先做**从示例到第一份作品**，接着补**项目里的交付记录和找回入口**。前者解决新用户不知道从哪里开始，后者解决有真实工作量的用户过几天回来时认不出最新成果。两项都能复用现有示例、编辑器、项目和导出逻辑。

PPT 编辑优先围绕已有人会做的事补齐，例如换一页版式、保留一份阶段稿、导出前检查关键页。小说章节管理和生成音视频需要独立的素材、编辑与交付流程，适合在当前报告和 PPT 路径有真实用户反馈后再排期。[当前支持范围](help/reference/boundaries.md)
