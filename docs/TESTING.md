## 换一台电脑时检查

Windows 10 x64 和 Windows 11 x64 的全新用户环境仍需独立复核。无需提供个人密钥，可只使用示例和本地模拟服务。

1. 解压 ZIP 到当前用户有写入权限的文件夹，保留配套 DLL、ui 和 samples。核对 SHA-256，启动后应出现纯净 / 智能选择。
2. 不填 API，选择纯净模式。断网后导入示例；验证视频暂停 / 跳转 / 全屏、音乐队列、照片编辑另存、PDF / EPUB 标记与笔记。
3. 退出再打开，确认模式、资料、阅读位置和笔记保留。移除收录记录时确认原文件仍在。
4. 切换中文 / English、深浅主题、100% / 150% / 200% 缩放、小窗口和减少动态效果；检查按钮文字、弹窗、侧栏和阅读区。
5. 新建测试私密文件夹，导入可公开的样例；验证密码、离开窗口自动锁定、重开后解锁。不要把它当作原文件加密。
6. 在智能模式使用本地测试服务验证配置、翻译和取消；检查设置中的地址 / 模型错误提示。真实服务测试需自行授权和承担计费。

开发者可以用自己的文件做真实文件回归：`tools/test-desktop.ps1 -Suites real-files -RealFilesFolder <文件夹>`。它会在隔离资料库中逐个导入、打开并检查文件，结束后移除记录，并核对原文件没有被修改。报告和截图只写入 `test-output/real-files/`，不会上传。

报告中附软件 / Windows / WebView2 版本、屏幕缩放、复现步骤和脱敏证据。请用[问题模板](https://github.com/ChenShoukang/kok/issues/new/choose)，安全问题见[安全报告](../SECURITY.md)。

## 常见首次使用问题

- **提示缺少运行环境**：安装 [.NET Framework 4.8](https://dotnet.microsoft.com/download/dotnet-framework/net48) 与 [WebView2 Evergreen Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)，再启动。无需 Node.js 或 .NET SDK。
- **无法写入资料库**：先把整个解压目录放到当前用户可写的位置，避免直接放在 Program Files；不要只移动 exe。
- **视频有声音但无画面，或不能播放**：检查实际编码；可使用“系统应用打开”。当前没有独立解码器，不下载来路不明的解码包。
- **窗口提示资料库已打开**：关闭使用同一资料库的另一个 kok 窗口；开发验证使用独立的 `--data-dir`。
- **需要日志**：默认位于解压目录下 `data/logs/kok.log`。发送前检查并遮盖个人路径或其他私人信息。
