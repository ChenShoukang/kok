# v0.12.0 Preview 验证

本版针对 v0.11.2 审计发现的三个 P0 交付缺陷与一个 P1 工具组问题。初版验证覆盖本任务成果回读、长资料精确分页读取、交付成品验收与失败补救，使用独立离线探针、原生测试、Node 检查与桌面套件。2026-11-12 在用户授权下追加 DeepSeek 实测与修复，结果和边界见下方追加记录。

| 验收项 | 检查方式与结果 |
| --- | --- |
| 本任务成果范围 | 批准创建文档后，宿主把真实成果 ID 加入本任务有效范围：回读、定点改稿、搜索均可命中，库外资料仍被拒绝；重放、重启与撤销后范围一致；宿主对创建/改稿自动回读。独立探针 22 项断言通过，并用真实任务引擎跑通「创建 → 回读 → 定点改稿 → 回读 → 完成」。 |
| 长资料精确读取 | `read_items` 返回连续原文并按 `offset`/`max_chars` 分页：12,277 字符资料 4 页、8,400/8,460 字符资料各 3 页读全；末页含 12,600 / 15,000 / 至少 60 份 / 验收负责人等末尾修订事实；覆盖率记录区间与内容摘要，未读、内容变更、旧抽样与 `recall_result` 回放不计为全文覆盖。 |
| 结果上下文裁剪 | 7,999 / 8,000 字符工具结果原样发送；8,001 / 10,000 字符结果保留约 7,972–7,974 字符并保留尾部事实，省略处明确标出 middle 省略与 `recall_result` 偏移提示，不再出现约 1,146 字符的突降（v0.11.2 审计值）。 |
| 交付成品验收 | 要求交付成品的目标只有读取时拒绝完成；创建且宿主回读后通过；PPT 实际页数与目标不符时拒绝并给出实际/要求页数，相符时通过；定点改稿缺少成功改稿记录时拒绝，改好并回读后通过；全文任务未读全时拒绝并列出未覆盖区间，读全后通过。 |
| 失败补救与工具组 | 同工具同参数的后续成功调用可补救已失败步骤，未补救失败、`uncertain_write`、跳过与撤销仍阻断 completed，`partial` 不受影响。默认报告任务工具由 24 个 / 18,050 schema 字符缩减到 11 个 / 9,463；PPT 任务保留创建、读取、复制与修改演示文稿工具；混合目标取类别并集，不因裁剪丢失所需写工具；讨论与只读任务不暴露写工具；显式 `allowedTools` 优先。 |
| 回归 | 全量原生测试 **1040 项通过**（v0.11.2 为 918 项）；`agent-model`、`agent-quality-unit`、`agent-task-samples` 与 `check-version` 离线检查通过；Lead 指定的 8 个 Agent 桌面套件（agent、agent-workflow、agent-reliable、agent-kernel、agent-runtime、agent-document-edit、agent-presentations、agent-quality）在真实 WebView2 与隔离资料库上 **8/8 通过**，测试使用本机模型夹具，无真实模型调用。独立离线探针最终构建上 **72/72 通过**。 |

## 2026-11-12 追加实测与修复

使用 `deepseek-flash`、隔离资料库与合成来源，累计 **38 次请求**，全轮硬上限 40 次。报告/PPT 单任务保持 6 次上限，定点修改保持 4 次；原有配置及用户资料未修改，隔离密钥配置已清除。

| 任务 | 用户改动版前测 | 本轮复测 | 验收边界 |
| --- | --- | --- | --- |
| 短报告 | completed，4 次，12.9 秒 | completed，4 次，13.9 秒 | 实际生成 Markdown，复测正文含 706 个汉字。 |
| 两处人数定点修改 | 修改已保存，因“不要创建新报告”被误判而 limited，4 次 | 中间一轮 partial；修复预算提示/批量替换指导后 completed，3 次，8.5 秒 | 最后一次用相同输入和目标逐字比对，仅两处 `6名志愿者` 变为 `8名志愿者`，文件身份及其余文字不变。 |
| 报告转 8 页 PPT | completed，3 次，12.1 秒 | completed，5 次，22.4 秒 | 两次均为真实可打开的 8 页 PPTX；第二次输入继承中间改稿的 6/8 人冲突，因此不算内容一致性通过，也没有证明提速。 |
| 三份长资料最终报告 | completed，6 次，17.8 秒，9/9 关键事实正确 | completed，6 次，21.4 秒，9/9 关键事实正确 | 复测仍漏掉开头的活动目标及“不收集联系方式”约束；总字符数也不能直接当作中文正文字数。最后追加来源开头摘录保留，验证了实际模型输入中同时存在这些内容与最新页，但未再跑完整模型生成。 |

本轮修复：否定创建要求不再触发新建成果验收；精确读取页不再二次裁掉中段；同轮读取分配统一字符预算；早期来源开头短摘录在剩余容量内保留；超上限/不可读来源不计全文覆盖；缓存保留截断标记；多来源 emoji 分页无缺口；请求提示明确当前轮与后续剩余次数，并支持同轮提交多处独立精确替换。

最终构建 **1053 项原生测试通过**（新增 13 项），`npm run check` 通过；`agent-document-edit`、`agent-presentations`、`agent-runtime` 三个最终桌面套件通过。测试中实际调用了结果拼装代码，断言 12k 精确页完整到达模型、并行读取不超容量、旧来源目标/隐私片段与最新修订页同时保留。

各轮结果保留于仓库外 `review/kokagent-optimize-2026-11-12/`：`summary.json`、`before/`、`after/`、`final-edit/`、`native-final.log`、`node-check.log`、`desktop-final.log`。这些是小样本诊断，不是统计完成率或最终版本四任务全部通过的证明；金额未配置价格，不能把日志中的 cost=0 解读为免费。

## 未做与限制

- 真实模型实测仅覆盖上述四类合成任务与一次定点修改专项复测；最后的来源开头保留修复只有最终模型输入断言与离线/桌面回归，尚无修复后的长报告完整生成证据。
- 交付验收与工具组按目标措辞推导，属启发式规则；本版已验证报告、PPT、定点改稿、全文读取、讨论/只读与混合目标，但未穷举所有用户措辞，后续仍需真实任务抽样。
- 三份长资料仍需 6 次请求；本轮输入 token 从 76,235 到 79,888，没有实现长任务成本下降。不能靠增大请求上限掩盖读取、计划或验收问题。
- 桌面套件只覆盖应用流程与真实 WebView2 环境，测试使用本机模型夹具，不含真实用户试用与专业视觉评分；未跑完整桌面包矩阵。
- 已知 UI 小问题（不影响功能）：任务结果卡会把本任务自己创建的成果同时显示为「打开文档」按钮和「查看来源」来源项，并计入“使用资料/来源引用”统计；两个入口均可正常打开文档，后续版本再优化该语义。
- 离线探针使用合成资料；未覆盖真实大文件（>100 MB 媒体/PDF）、并发任务与长任务压力场景。
