# v0.12.2 Preview 验证

本版针对 v0.12.1 复查发现的 12 项问题（`review/kokagent-review-v0121-2026-11-12/本轮复查问题清单.md`，含 23 行无 API 本地探针场景：21 个复现问题 + 2 个正反对照）做缺陷修复：建立“当前有效任务要求”状态机（按用户消息顺序更新交付物、页数、字数/单位、格式、来源范围、改稿与全文要求、chat-only），验收绑定**最终交付物 ID/版本**，统一文档与演示稿的读取覆盖（PPT 逐页覆盖、改稿后回读），显式格式/计量单位/聊天正文长度纳入验收，约束保留优先最终修订。全部验收离线完成，**未调用真实模型 API、未运行 live 评测**。

| 验收项 | 检查方式与结果 |
| --- | --- |
| 当前有效要求状态机（#1–#4、#6） | 按消息顺序应用“替换/取消/最后一次覆盖”：800–1200 字改 300–500 字后按新范围验收；“取消字数限制”清空旧范围；同一条消息“制作8页PPT，改为5页PPT”得 5 页；“改成写报告”替换 PPT 交付、“先不要修改，只分析”取消改稿、“只看开头”取消全文读取；“不要做3页PPT，请做8页PPT”“不要创建旧版报告，请创建新版报告”仍要求正向交付；“重点核对第二份”不缩窄来源（3 份仍全读），“改为全部资料”恢复 3 份；chat→save 后工具组与宿主校验同步开放 `create_document`，save→chat 后关闭。用户原始复查探针对应行由 REPRODUCED 全部变为 NOT_REPRODUCED。 |
| 最终交付物绑定（#5、#9–#11） | 同一任务的多个成果只认**最后创建且未撤销**的最终 ID：双文档“先建150字已读、最后建20字已读”被拒（字数在最终文件上不符），反向顺序通过；双 deck 只认最终 deck 的真实页数（8 页请求 + 最后 5 页 deck → 拒绝），反向顺序通过；最终成果未回读时拒绝；显式 DOCX 要求交付 MD 被拒、真实 DOCX + 回读通过；字符/汉字/英文单词三种计量单位分别计数（149 字符英文文档按“100–200 字符”通过，不再按汉字 0 计失败）；chat-only 短答复（“摘要：项目可行。”）按 800–1200 字要求拒绝，长答复通过。 |
| 读取覆盖与改稿回读（#7–#8） | `read_presentation` 记录逐页覆盖（`mode="exact-read"`、`domain="presentation"`、页区间/摘要）；8 页成果只读 1 页时验收拒绝，读满全部页后通过；作为**来源**的 8 页 PPT 读满全部页计入全文覆盖（不再报“尚未读取任何原文”），只读 1 页不算；`replace_document_text` 修改后没有当前回读时拒绝完成，补读后通过。 |
| 约束保留最终修订（#12） | 同一资料前 10 条旧要求 + “最终修订要求预算上限为八万元，以上原方案作废”的夹具中，保留区包含最终修订（标题注明“优先当前有效/最终修订，旧版本可能已废止”）；普通约束句仍正常保留。 |
| 回归 | 全量原生测试 **1296 项通过**（v0.12.1 基线 1195，新增 101）；独立离线探针 **72/72 通过**；**用户原始复查探针（源码未改）23 行中 21 个复现行全部变为 NOT_REPRODUCED、2 个正反对照仍通过**；`check-version`（0.12.2）、`agent-model`、`agent-quality-unit`、`agent-task-samples`（30 任务样本）通过；5 个变更 JS/UI 文件 `node --check` 通过；`check-docs` 与 `audit-release`（无凭据/私有数据模式）通过；Lead 指定 8 个 Agent 桌面套件（agent、agent-workflow、agent-reliable、agent-kernel、agent-runtime、agent-document-edit、agent-presentations、agent-quality）在真实 WebView2 + 隔离资料库上 **8/8 通过**，使用进程内模型夹具、无真实模型调用。 |

## 未做与限制

- **真实模型端到端未测**：全程未调用真实模型 API、未设置 `KOK_LIVE_AI`，live 评测未运行；本版只能证明宿主可验证行为（要求状态机、工具可见性、最终交付物验收、读取覆盖、改稿回读、聊天长度、约束保留）在离线条件下正确，不能证明真实模型会按最新要求产出、主动读全/回读或修复交付缺陷，也不能给出真实任务完成率、写作质量、请求数与费用数字。
- 探针使用合成资料与固定目标文本；桌面套件使用进程内模型夹具，不代表真实用户长任务、并发与专业视觉质量。
- 要求解析为启发式规则，已覆盖用户复查 23 行场景与新增契约断言，但未穷举所有措辞；真实任务抽样仍必要。
- 桌面范围只覆盖 Lead 指定的 8 个 Agent 套件（完整桌面矩阵与用户试用不在本轮范围）。
- 发布包以 Lead 权威构建或流水线重建为准；本地构建 SHA 会因构建时间不同而字节不同。
