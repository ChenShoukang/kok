# v0.13.0 验证记录

本版新增 Deep Agents 研究运行时。验收同时覆盖 SDK、原生文件与审批、桌面界面，以及一个使用 DeepSeek API 的真实任务。以下结果对应本地未发布的构建，不代表公开发布状态。

## 已完成的验证

| 项目 | 结果 | 范围 |
| --- | --- | --- |
| 原生构建与回归 | 1318 项通过 | 兼容内核、文件工具、范围/审批、交付验收，以及 16 项新研究内核集成断言和 6 项来源修订识别断言 |
| Node 研究运行时 | 5 项通过 | 实际 SDK 工具中断/恢复、压缩检查点重启、错误密钥脱敏、逐请求许可与重定向拒绝、合并 worker 的真实 HTTP 路径 |
| 桌面 agent-research | 通过 | 默认研究内核、中文来源、原生审批、真实 DOCX、回读、完成；3 次本地模拟模型请求 |
| 桌面 agent-document-edit | 通过 | 兼容内核的精确改稿、审批、预览、撤销、版本与手动修改保护 |
| 桌面 agent-reliable | 通过 | 兼容内核的重载恢复、暂停审批、会话切换、队列恢复、私密模式与界面行为 |

固定响应的历史桌面套件明确使用兼容运行时；新研究套件使用 SDK。两者分别验证，不能把历史套件的通过数都算作新内核的能力。

## 真实 API 测试

使用用户已授权的 DeepSeek 密钥，仅发送合成资料，模型 deepseek-flash。两次尝试共用同一计数文件，**累计 9 次模型 HTTP 请求，没有重置计数，未超过 10 次总上限**。

- 第一次尝试在修复前用了 6 次请求，未完成。模型已创建报告，但旧规则将“采用最终修订预算”误识别为定点改稿，错误要求额外修改文件，导致达到请求上限。这次失败保留在证据中。
- 修复来源修订的意图识别，并让 SDK 直接使用宿主已有回读后，同一类任务 **3 次请求、约 19 秒完成**：完整阅读两份合成来源，生成一份 DOCX 活动研究报告，审批后保存并回读。
- 保存的报告有 **501 个汉字**，满足 400–600 汉字要求；实际文件包含 8 万元最终预算、禁止收集手机号、报名待确认与来源说明。输入 token 合计 20,474，输出 3,190，缓存命中输入 13,056；缓存 token 是输入的子集，不能重复相加。
- 没有配置金额单价，因此不报告人民币费用。原计划的第二个真实改稿任务未执行，以保留既定总请求上限；改稿能力的本版证据来自离线与桌面兼容回归。

这证明一个代表性研究交付任务能完成，不等于通用成功率，也不证明专业研究结论或引用支持关系已经全面核实。

## 证据与限制

原生与桌面日志、修复前后真实调用记录、计数文件、生成的 DOCX 保存在仓库外 review/research-v013；桌面带运行组件指纹的记录保存在 test-output/research-v013-desktop-final。加载比较保存在独立的 kok-agent-v2/bench。API 密钥不写入报告、源码、日志或发布包，隔离测试配置使用后已清理。

本轮没有覆盖真实长 PDF、扫描件 OCR、多模态、联网研究、多模型矩阵、并发、超长会话或专业写作质量评审。SDK 检查点当前绑定 Node 主版本并有大小上限。新研究界面隐藏旧手动压缩、委派与压缩细调入口，直接调用旧手动压缩接口会明确拒绝；这些高级能力需要以后逐项映射到 SDK。本版优先验证单 Agent 研究交付。

构建/语法、文档链接、版本一致性与发布包审计由本地检查执行；发布包和校验文件以最终打包产物为准。
