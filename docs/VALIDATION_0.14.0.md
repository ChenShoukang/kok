# v0.14.0 实现与验证记录

本版目标是建立可继续扩展的通用 Agent 基础，首先解决任务恢复、状态一致、真实产物与长作业执行。它不是九类专业生产力能力同时完成的版本。

## 计划落实

| 计划项 | 本版实现 | 边界 |
| --- | --- | --- |
| A01 基线与能力盘点 | 保留既有资料库、编辑器和审批；运行时输出九类能力目录 | 能力状态按现有工具与工作区配置计算，不把编辑器界面当作完整 Agent 引擎 |
| A02 版本化契约 | TaskSpec、Asset、Capability、step 协议 v1 与作业记录 v1；生成 JSON Schema | TaskSpec 是现有交付要求的只读投影，仍沿用已有自然语言规则，并未解决所有需求理解问题 |
| A03 TypeScript 内核 | 严格类型检查，打包为独立 worker；Deep Agents 1.16.4 / LangGraph 1.7.3 | C# 桌面、审批、工具和任务日志保留，仓库路径 runtime/research 为兼容继续沿用 |
| A04 通用任务入口 | 同一任务附带能力意图、可用性和相关指导，保留本机授权工具 | 意图识别目前基于规则；每个领域的高质量流程需在后续版本逐项接入 |
| A05 项目与资产关联 | 原生来源、文档和工作区文件投影项目 ID、来源操作、版本及可用性 | 沿用既有项目存储；尚无覆盖所有媒体编辑器的统一资产数据库 |
| A06 旧执行循环隔离 | AgentLegacyRuntime 保留历史任务与 JSON 协议路径 | 共享的审批、验收、工具和任务状态继续复用 |
| A07 异步作业 | start/read/wait/cancel_command_job；单库最多同时 2 个，默认 600 秒、最长 3600 秒 | 本版首个作业后端为命令进程；不是媒体渲染或云端作业系统 |
| A08 可恢复状态 | 公开 put/putWrites/deleteThread 接口记录与恢复；v0.13.0 私有格式仅作迁移入口 | 新快照压缩上限 512,000 字节；操作日志仍可能随长任务增长，未承诺无限时长 |
| A09 设置与目录 | 显示九类能力实际状态，提供作业查询与取消界面 | 照片、视频、音乐为部分可用；表格、电脑操作完整执行器待接入 |
| A10 构建与发布 | 版本统一、原生/运行时/桌面验证、发布 ZIP 与 SHA-256；CI 增加新运行时检查 | 具体结果见下表；发布只通过项目现有门禁流程 |

## 使用与恢复

1. 完整解压安装包，保留 runtime 目录；新任务按需启动随包提供的 Node 24 worker。
2. 在“能力与权限”中指定已有工作目录并启用执行。命令逐项显示可执行文件、参数、工作目录、时限和声明输出供审批。
3. 使用 start_command_job 启动后，模型应调用 wait_command_job 或 read_command_job 验证真实结束；运行中作业不会被当作成功交付。
4. 从任务“更多”菜单进入“后台作业”，查看本机结果或停止任务所属进程组。停止状态先显示正在停止，确认结束后才显示已取消。
5. 任务日志和作业结果使用 Windows 当前用户 DPAPI 加密。程序重启会将未完成作业标记为中断，不自动重复执行已批准命令；确认文件状态后再决定下一步。

## 已知边界

- 未启用 AppContainer 时，批准的命令以当前 Windows 用户权限运行；工作目录约束不是进程沙箱。内置文件工具拒绝父目录越界和嵌套符号链接，但无法替代对任意外部程序的系统隔离。
- 作业历史最多保存 1,000 条，界面展示最近 100 条；达到上限会明确拒绝新作业，不静默丢弃执行证据。
- 命令声明输出用于追踪真实文件，不代表这些文件已经通过内容、画质、音乐质量或版式验收。后台等待不请求模型；模型再次规划和总结仍计入请求与费用。
- 新检查点使用公开接口，但仍绑定固定版本的 SDK 序列化约定，跨 SDK 升级必须继续做迁移测试。旧 V8 快照迁移要求同一 Node 主版本。
- 图像生成、专业视频 Agent 时间线、音乐生成/编曲/分轨、完整电子表格、浏览器及桌面操作尚未作为完整工作流交付；保留在[详细计划](PROJECT_PLAN_0.14_TO_1.0.md)中。
