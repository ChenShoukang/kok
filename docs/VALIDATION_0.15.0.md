# v0.15.0 实现与验证记录

本版在 v0.14.0 通用执行底座上，补足代码工作区与本地网页的可验证任务流程。没有更换 Deep Agents / LangGraph 内核。

## 使用入口

在 Agent 的“能力与权限”中选择并启用本地工作区，再直接输入任务。补丁和命令会展示具体操作，批准后执行；完成页的“工作区成果”可以在文件夹中定位实际文件。

- 代码修复示例：“检查当前工作区，修复 sum.ts 的加法错误，保留已有改动，运行项目适用测试，交付源码和测试结论。”
- 新建示例：“在当前空工作区创建一个 TypeScript 加法函数及可运行测试，执行测试后交付实际文件。”
- 网页示例：“启动当前工作区的本地网页服务，在 127.0.0.1 的页面填写表单并验证结果，完成后停止本任务启动的服务。”

命令执行需要本机已有适用的解释器、编译器或项目依赖；内置 Node 可供 JavaScript / TypeScript 使用。实际命令和网页结果能被检查，并不保证任意复杂项目都能在一次任务内完成。若用户设置的请求上限不足，会保留已完成工作并显示实际状态。

## 实现范围

| 计划项 | 本版实现 | 限制 |
| --- | --- | --- |
| C01 仓库与环境 | 项目标记、实际可执行文件识别、Git 状态与差异 | 识别可执行文件不等于完整构建环境已验证；环境缺失明确报告 |
| C02 文件与补丁 | 分段 UTF-8 读取、搜索、原始字节 SHA-256、工作区身份保护、唯一匹配的精确替换与新文件创建 | 读取最多 4 MB，单次结果最多 400 行；补丁结果最多 200,000 字符 |
| C03 长命令 | 沿用可审批、查询、等待、取消的后台作业 | 每库最多并行 2 个；重启不自动重跑 |
| C04 实际验证 | 输入文件哈希与工作区身份、真实退出码、验证期间变动检查和最终完成校验 | 主机核对证据与当前版本；命令是否充分覆盖业务行为仍需任务判断 |
| C05 服务和网页 | 启动自己拥有的服务、隔离 WebView2、观察/输入/点击/选择、等待后置条件、停止服务 | 仅明确的本机 HTTP 来源；不访问远程网站、个人浏览器、文件输入或自动下载 |
| C06 修改与恢复 | 过期补丁拒绝覆盖、已应用补丁幂等、旧冲突经新批准的有效补丁解除 | 不提供覆盖任意命令副作用的通用撤销 |
| C07 任务评测 | 实际 TypeScript、Python、C# 程序及桌面任务验证 | 不是任意语言、仓库与网站的通用成功率 |
| U01/U02 网页基础 | 按任务隔离的浏览器、固定来源、密码字段排除、新鲜页面与控件检查 | U03–U08 的 UIA、视觉操作、多软件恢复和广泛兼容性仍是后续工作 |

## 验证

本地原生验收 **1355 项通过**；TypeScript / Deep Agents 运行时 **9 项通过**。前端、版本、文档链接和 PowerShell 检查通过；依赖审计为 **0 漏洞**，源文件与 Git 历史隐私审计通过。原生检查包含从空工作区发现身份、批准创建首个文件和实际回读的过程，以及只读评审和顺序测试指令的回归。

实际 ZIP 的完整 **30 组桌面回归通过**，包括研究、代码、本地浏览器、恢复、MCP、文档与 PPT 的真实操作和导出。补上空工作区身份返回后，对最终候选 ZIP 再次运行研究、执行基础、代码和浏览器 **4 组检查，全部通过**。本地 Node 为 24.18.0；官方发布继续由双 Windows 构建和正式 ZIP 的完整 30 组桌面门禁把关。

真实模型验收使用用户授权的 DeepSeek API（`deepseek-flash`）：读取实际代码、精确修复 `sum.ts` 加法错误、保留用户已有注释、执行 `verify.mjs` 的两条断言，实际退出码为 0，生成并读回 `result.json` 的 `{"value":5}`，任务最终为 `completed`。主机核对改动范围、当前源码哈希和验证证据，均通过。共 **8 次请求**，输入 60,002 tokens（其中缓存 51,456），输出 1,332 tokens；这些是本次 API 用量，不是通用效率基准或金额估算。

该任务曾因验收脚本读取了不含参数的摘要字段而暂停，修正脚本后续跑原任务；原 8 次请求总账和检查点均保留，没有重置上限。因此不将续跑阶段耗时当作端到端速度指标。测试结束后清除了临时 API 配置，密钥不进入仓库或安装包。

桌面离线模型验收用于验证编排、审批和真实文件/进程/页面行为，不能代替真实模型质量评测。代码样例包含 Git 已有未提交改动；浏览器样例包含异步页面更新、密码字段、不同来源资源拦截和服务停止。

## 实用性与效率修复

- 命令与 Git 输出在后台读取，避免同步等待异步管道时阻塞 WinForms 界面。
- 代码任务使用针对工作区的工具组合，省去无关资料库目录与重复的旧文件工具；研究任务省去不需要的命令工具。
- 补丁审批展示原文与替换内容；作业和页面结果保留实际退出码、页面状态及文件验证信息。
- 工作区成果作为真实资产保留，读取不会把产物降为普通来源；完成界面可直接在文件夹中定位。
- 已经正确的源码可以经实际检查后完成，不要求制造无意义补丁。任务完成仍取决于当前工作区与文件版本的真实证据。
- 讨论和只读模式不强迫执行命令；解释中英文 `add` 函数不会被误当作新增功能。明确不运行测试时不会被描述中的“测试”一词覆盖，后续允许或取消测试的消息按顺序生效。

## 重要边界

- 内置文件工具拒绝越界、嵌套符号链接、Windows 设备与尾点别名、环境凭据路径；代码内容中的已知密钥格式会脱敏。这不等于识别了所有可能的私密数据。
- 未启用 AppContainer 的外部命令拥有当前用户权限；工作目录不是操作系统沙箱。
- 搜索明确限制访问量与输出量，并标记截断；依赖、构建目录、凭据和符号链接不被递归搜索。
- 代码验证要求声明 inputs，且验证后的内容与工作区身份仍匹配；未运行、非零退出或过期检查不能被当作当前通过。
- 本地浏览器只操作批准的同一来源；每项修改操作需确认。页面文本是不可信数据，不能扩大权限。会话关闭或重启后不会重放旧点击。
- 音乐、视频、图像生成与完整表格能力仍沿用详细规划，当前代码/浏览器版本不将它们标为已完成。

技术实现参考 [WebView2 导航事件](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/navigation-events)与[官方 CoreWebView2 API](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2)。发布门禁要求双 Windows 构建、运行时及实际 ZIP 的桌面集成检查通过，记录见 [GitHub Actions](https://github.com/ChenShoukang/kok/actions/workflows/build.yml)。
