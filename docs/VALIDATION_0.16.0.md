# v0.16.0 实现与验证记录

本版按“先迁 Agent 业务主体，桌面壳分步迁移”实施。默认新任务由 TypeScript 承担需求、工具路由、交付验收与来源/成果结构检查，继续复用锁定的 Deep Agents / LangGraph。C# 保留 Windows、权限、日志、恢复及真实 I/O；旧任务与显式 native / JSON 路径保持兼容。[主体说明与后续迁移](AGENT_TYPESCRIPT_0.16.0.md)

## 可使用的变化

- 代码任务完成后，在同一会话输入“继续优化这个函数”，可以从原生会话分支接续实际工作区文件。当前目标和权限优先，先读取当前内容，再执行新的精确补丁与验证。
- `review_sources` 区分已解析、未读、部分读、完整读和版本过期。检查本身不会增加阅读覆盖；引用是否支持结论仍需进一步判断。
- `inspect_document` 检查实际 MD/TXT/DOCX 的正文、长度、结构和指定栏目；`inspect_presentation` 检查实际 PPTX 已解析对象的页面边界、文本框交叠、字号和估算溢出。
- `edit_presentation` 支持 `bounds` 与 `font_size`，使用真实页面和对象 ID 修复位置、尺寸及字号。未涉及页面的原生 XML 保持不变。
- `render_presentation` 在本机已安装且空闲的 PowerPoint 中逐次批准渲染最多 8 页 PNG；图片与源文件版本、页数、尺寸和哈希绑定，界面可查看实际页面。
- 命令退出 0 但缺少声明输出文件时标记失败，缺失文件不会显示为可用成果。PPT 文本因输出限制而截断时，该页不计作完整阅读，可缩小页面窗口或使用精确文本分页继续读取。

## 使用与质量边界

- 未安装 Office 时仍可创建、读取、结构检查和定点修改 PPTX，实际渲染需安装适用的 PowerPoint。当前不捆绑 Office，也不提供其他办公软件渲染器。
- 正在运行个人 PowerPoint 会话时拒绝自动渲染；仅打开本任务复制的只读文件。宏、OLE/嵌入对象和非超链接的外部关系包在打开前拒绝。
- 渲染是独立 STA 工作进程，超时或取消停止本任务工作进程。Office 自身失去响应时可能需要用户处理残留会话；不会按名称杀死个人 Office。
- `rendered=true` 只表示有实际图片；`visualReviewed=false` 明确表示没有完成视觉评审。结构检查不验证事实、引用支撑、图片审美、实际字体替换或所有高级 Office 对象。
- 密集文字容量和交叠属于估算警告，避免将合理设计直接视为错误；可确定的完整页面外对象需修复后交付。未解析对象会说明限制。
- 本版没有宣称已完成所有高质量 PPT 要求；图表/素材工具、专业视觉自动评审与更广的兼容样例仍在[详细规划](PROJECT_PLAN_0.14_TO_1.0.md)中。
- 语言迁移不会自动提高模型能力或令任意任务成功；任务质量仍由模型、工具、实际验证和可用资源共同决定。照片、视频、音乐、表格和通用电脑操作按各自里程碑继续推进。

Office 适配依据 Microsoft [Presentations.Open](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.presentations.open) 与 [Slide.Export](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.slide.export) 接口实现；本机实测范围见上文。
