# v0.16.1 实施范围与验证

本版是[新路线](NEXT_PHASE_0.16_TO_0.18.md)的首批可靠性改进，继续使用 TypeScript / Deep Agents 1.16.4 / LangGraph 1.7.3 和现有 C# 原生宿主。照片、视频、音乐、新桌面壳及完整专业 PPT 质量仍按后续任务推进。

## 实际行为

- “报告先取消，只保留 PPT”：取消文档要求及其长度/格式约束，保留 PPT 页数。
- “不做 PPT 了，只写 DOCX 报告”：切换到实际文档交付，取消旧 PPT 页数。
- “不要新增成果，只检查已生成文件”：不再强制创建文件，不沿用旧文件的长度要求作为聊天验收。
- 修改输出格式、页数或字数是交付要求更新；不会单凭“改为”强制产生原地改稿记录。指定正文/页面的修改仍需实际修改与回读。
- 被新要求取消且从未开始执行的提案保留在日志中，但不阻塞当前任务的完成判断。用户明确拒绝、实际执行失败和结果不确定的操作不享受该例外。
- 撤销待审批工具后，恢复旧中断以返回真实跳过回执，同时从新模型工具列表移除该工具。HTTP 请求先完整提供对应 tool_call_id 的工具结果，再提供新用户要求；检查点保存原始消息，不为修正服务协议而丢弃历史。
- 连续两轮使用同一稳定读取工具、相同参数、相同当前结果时提醒改变路径；第三轮仍相同则停止重复模型调用，以 partial 保留工作。补充要求可接续同一任务并重新核对状态。
- 分页、当前结果/版本变化、插入其他操作、同一轮并行读取会中断重复计数。写入、后台作业查询/等待和网页观察不纳入这项停止规则。
- 只在模型输入中替换完全相同的成功原生结果，保留最近一份全文与原调用 ID。公开检查点与原生日志保留全部原始消息；缺少 recall_result 时不启用该投影。错误、版本和主机回读标识有差异时不合并。

## 已建立的基线与诊断

[18 场景清单](../tests/fixtures/reliability-v0161.json)固定了研究、文档、PPT、代码、组合各 3 项和 3 项边界场景，包含输入资料与交付判断要求。`npm run check:reliability` 检查规划结果并输出来源/题目哈希；`--output` 可以记录结果。当前这条命令只检查需求判断，不能证明成品质量、真实模型成功率、代码验证或边界场景的实际行为。

对同一冻结题目的规划检查，v0.16.0 为 **11/18**，修复后为 **18/18**，均为零模型请求。它们是开发题，不能标为未见题。两轮完整 18 场景真实模型评测、保留素材泛化与全领域质量评分尚待后续实施。

执行追踪增加 `performance`：观察到的模型/工具累计耗时、确认等待、首个文件保存回执时间、非缓存输入、重复回执节省字符和进展提醒/停止次数。累计时间可能重叠，不能相加为总耗时；墙钟时间包含暂停和等待。首个保存回执不代表该成果已经通过质量评审。用量估计保留 estimated 标识，未配置价格不输出推算金额。

`npm run measure:business` 对实际打包 Node/业务 worker 运行 12 次纯规则调用。首次本机测量短进程墙钟中位数约 **51 ms**；开发 Node 中的本地纯规则中位数约 **0.057 ms**。后者不是与打包进程同条件的完整对照，不能用它推算端到端收益。本版保留短进程及计划缓存，不增加常驻服务。

## 验证记录

本机完整原生检查 **1,389 项通过**，其中聚焦 SDK 链路的 24 项包括审批、DOCX 回读、重复读取停止、同任务接续，以及取消待审批报告后真正交付 8 页 PPT。TypeScript/运行时 **38 项通过**，覆盖需求槽位、旧检查点恢复、精确重复结果的实际 HTTP 投影和检查点全文保留、退役待审批工具的恢复及严格消息顺序。前端/版本/文档与 PowerShell 5 检查通过，主项目和运行时生产依赖审计均为 0 个已知漏洞。

正式发行门禁继续要求 Windows 2022 / 2025 构建与原生回归，以及实际 ZIP 的完整 **31 组桌面集成检查**，其中研究套件还检查新增诊断数据和界面。只有本版门禁通过才上传 Preview，状态与发行证据见[GitHub Actions](https://github.com/ChenShoukang/kok/actions/workflows/build.yml)。历史版本的通过数不代替本版验证。

本次依照既有用户授权，使用隔离的合成资料测试 DeepSeek 需求调整；请求进入独立本轮账本，既有 v0.16 的 38 次记录保留。结果与未完成尝试均计入本轮用量，临时凭据在 finally 中清除。

真实模型为 `deepseek-flash`，三个定向场景最终均为 completed：

| 场景 | 实际结果 | 累计请求 | 时间口径 |
| --- | --- | ---: | --- |
| 取消报告，只保留 PPT | 实际 8 页 PPTX；没有创建被取消的报告；原资料保留 | 9 | 首次 3 次请求暴露工具消息协议 400；保留原账本与检查点，修复后续跑 6 次，续跑约 28.72 秒，不作为端到端耗时 |
| 取消 PPT，改交 DOCX | 实际 489 汉字 DOCX，包含最终预算/人数、隐私限制与待确认项；没有额外 PPT | 4 | 约 35.09 秒，含合成测试中的调整与审批 |
| 不新增成果，只检查已有文件 | 读取已有报告，原始文件哈希不变，无新成果文件 | 3 | 约 20.54 秒，含调整 |

本轮合计 **16 次请求**，其中首次调试的 3 次未完成尝试保留，不重复算成成功样例。三个任务最终成功只能支持这些定向场景；不是 18 题基准或通用成功率，也不能与旧版不同任务的耗时直接比较。全部测试资料、任务日志和账本在隔离目录保留，临时 API 配置及备份已清除。
