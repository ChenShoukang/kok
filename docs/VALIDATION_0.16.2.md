# v0.16.2 实施范围与验证

本版继续沿[近期路线](NEXT_PHASE_0.16_TO_0.18.md)落实 Q01/Q02 的首批交付检查，并把原来只做规划的 18 个开发题接入实际模型、运行时、审批和文件验证。内核仍为 TypeScript / Deep Agents 1.16.4 / LangGraph 1.7.3，C# 负责桌面与原生操作。

## 结论与原文

`review_claims` 每次接受最多 12 条结论、来源 ID 和精确引文，返回当前来源版本、规范化 UTF-16 起止位置、原文行号及原始阅读调用 ID。宿主采集真实文本和阅读记录，TypeScript 只作本地规则计算，不为检查额外调用模型。

- `anchored`：引文唯一定位，且当前版本的实际阅读区间覆盖整段引文。
- `unread`：引文存在，但没有足够当前版本阅读。检查本身不增加阅读覆盖。
- `stale_reading` / `stale`：阅读已过期，或调用者要求的来源版本已变化。
- `ambiguous`：同一引文出现多次，需提供规范化文本中的明确偏移。
- `not_found` / `unavailable`：引文不存在或来源不可用。

支持文本来源的 `read_items` / `read_document` 阅读记录；PPT 按页读取不冒充文本区间。只有正文和笔记确实完全相同，才允许两个文本域的阅读记录互认。位置采用换行统一为 LF 的文本坐标，与规范化覆盖记录一致。

可传 `artifact_id`，在实际保存的可编辑 MD/TXT/DOCX 版本中定位 `claim` 原句，同时记录成品签名。未保存的恢复内容不算可验证成品。此项证明原句存在，不证明整份报告的每条结论都已核验。

`supports`、`contradicts`、`inference`、`unverified` 是调用者提出的关系；始终返回 `semanticVerified=false`、`relationshipAuthority=caller_proposed`。数字 token 不一致只给复核提醒，不能处理单位换算或证明逻辑支撑。宿主标记本任务生成的来源为 artifact，用成品作为依据会给出 `artifact_used_as_source`，提醒仍需原始输入依据。界面区分这些关系和实际原文定位结果。来源变更后的结果保留原版本，不作为新版证明。

## 报告必需章节

明确的栏目/章节清单进入当前文档要求；“报告应包含目标、流程、风险和待确认事项”也可识别为常见结构。普通事实列表不强行转为章节。后续“栏目改为背景、结论”替换清单，“取消章节要求”清除该限制，取消报告也会清除旧清单。

检查实际保存文件的独立标题和非空正文，支持 Markdown、中文编号及 TXT/DOCX 的独立栏目标题；代码围栏中的标题不计。仅在正文提到“风险”或只留下空“风险”标题，分别报告 missing/empty。结果包含标题行号、正文大小和具体缺项。

新的默认 TypeScript 任务采用 `artifactReviewVersion=2`，在最终验收中使用用户当前清单。模型自行传给 `inspect_document.required_sections` 的额外清单不会变成用户交付门槛。创建和修改的原生回执附带检查结果；不合格时拒绝提前完成，并只要求补齐缺项。旧任务的版本 0/1 不增加新章节完成条件。

这项检查证明结构存在，不能证明正文充分、观点正确、用途和受众匹配，也不检查 DOCX 分页视觉质量。用途/受众的完整结构化要求、跨章节语义一致性及专业排版仍需后续实现。

## 真实完整任务评测入口

题目来自 [18 场景清单](../tests/fixtures/reliability-v0161.json)：研究、文档、PPT、代码、组合各 3 题，另有 3 项边界题。此前的 `check:reliability` 仍只检查规划，不混入完成率。

在获得 API 测试授权后，先构建当前应用，再在 Windows PowerShell 5.1 中显式运行：

```powershell
.\tools\evaluate-agent.ps1 -Live -ApiKeyFile '本机密钥文件绝对路径' -Round round-1
```

可用 `-Cases research-conflict,document-length` 选题，`-Suite quality` 执行额外两项报告题，`-Model` 指定 DeepSeek 模型，`-MaxRequests` 设置整个评测目录累计的请求上限（最多 150）。在 PowerShell 命令行直接调用脚本时传数组；用 `powershell.exe -File` 传多题时应使用脚本包装数组。不能复用已有轮次目录，也不会清空累计账本。

评测器实际调用打包运行时及模型，经宿主批准写入、回读并重新打开文件；PPT 检查真实页数和未改页面字节，代码检查原注释、实际补丁与 Node 执行记录。审批仅限测试资料和工作区，命令只允许已发现的 Node 做版本查询或运行种子 `sum.ts`。它不代表人工逐项操作体验。

每题保存完整输入、来源内容/哈希、结果、失败项及脱敏执行追踪；整个轮次记录来源清单和候选指纹。先前代码任务使用真实原生读取日志作为种子，并非另跑一次完整模型任务。边界题分别验证额度用尽、取消/停止和实际渲染限制，不加入普通交付成功率。开发资料不是未见题；字面事实、结构和文件检查不是盲测语义评分或专业视觉评审。

API key 只在测试进程中读取，临时设置使用现有本机加密配置，结束后清理配置及备份；不写入源码、评测结果或日志。API 请求计入目录下的持续账本，包括失败和重试。运行中断时保留现有题目记录和账本，后续选新轮次名称继续，不以重置计数重跑。

## 验证记录

新增 7 项 TypeScript 检查、16 项原生检查和实际桌面任务：验证未读/间隙/过期阅读、重复和虚构引文、成品原句、自证提醒、空章节拒绝、精确修复、当前代码要求与随包 Node 发现。完整运行时 45 项通过；候选包继续执行全部原生检查和 32 项发行 ZIP 桌面套件。

### 实际 DeepSeek 结果

本批模型为 `deepseek-flash`，18 题首轮加受影响定点重测和额外报告题，**累计 132 次 API 请求**，包括失败与重试，上限 150；保留原始账本及每轮输入/结果。公开汇总见 [EVALUATION_0.16.2.json](EVALUATION_0.16.2.json)。v0.16.1 的 16 次请求是独立的旧批次，不在本批重置或隐藏。

| 批次 | 范围 | 请求 | 结果 |
| --- | --- | --- | --- |
| 首轮 | 15 项交付题 + 3 项边界题 | 79 | 原评分 12/15 交付通过；修正已记录的空格误判后 13/15；边界 3/3 |
| 代码定点复测 2 | 中途要求运行测试、可信会话接续 | 18 | 前者通过，后者 9 次额度内未完成；失败保留 |
| 新报告题首轮 | 必需章节、后续章节变更、成品原句依据 | 13 | 两题文件已完成但各有一项更强检查失败，暴露未关联成品原句及栏目解析边界问题 |
| 新报告题复测 | 修复后的同两题 | 13 | 两题通过；独立核查原始输入 ID 与最终成品签名也通过 |
| 代码接续复测 3 | 保留用户注释、修复加法并实际验证 | 9 | 通过；仍接近上限，不据此宣称整体提效 |

首轮长资料回答正确写出“8 万元”、60 人和中间的手机号限制，并真实覆盖 15,045 字符；评分器最初仅接受无空格“8万”，修正后另存复核记录，原始失败文件不修改。首轮两项代码题被过窄的测试器命令批准条件中断，实际 Node 路径与版本查询后续纳入允许范围；不能直接称为模型未完成。

随后复测还暴露代码接续过度扩写及使用另一个 Node 带来的返工，补上必要改动优先、随包 Node 发现，以及当前提示中的真实后续要求。报告复测修复了“章节清单后面的长度/格式保持被当作新栏目”，并明确区分成品原句与原始资料依据。新的报告分别有 5、11 条原句定位同时对应输入来源和最终成品版本，仍不作语义支撑认证。

这些是开发题和不同候选的定点验证，不是第二轮完整同条件评测，也不是通用成功率。不能把首轮及重跑挑选汇总为“18/18 一次完成”。独立未见素材、完整两轮门槛和专业视觉评分仍未验收。

## 后续顺序

1. 按[开源复用优先路线](OPEN_SOURCE_REUSE_PLAN.md)先推进有类型的需求增量和公开会话机制对照，减少上层自写规则；补齐两轮同题与保留素材验证，不给尚未完成的评测或 20% 效率目标标记达成。
2. 扩展结论依据记录与用户可核查的来源入口，处理需要模型判读的冲突/推论，同时记录不确定性。
3. 完善报告用途、受众和跨段落一致性；保持局部修复及真实文件验收。
4. 推进 PPT 设计/布局、真实数据图表、渲染和视觉评审闭环；之后按原路线推进照片、视频、音乐与新桌面壳。
