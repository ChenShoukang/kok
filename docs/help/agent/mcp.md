# 外部工具 MCP

MCP 让 Agent 调用你自己准备的外部工具：本地程序或远程服务提供的工具。这一页说明如何连接服务、授权工具，以及使用时要承担的风险。

## MCP 是什么

MCP 是让 Agent 发现并调用外部工具的协议。kok 支持 **本地程序（stdio）** 和 **远程 HTTP** 两种连接方式；外部工具的每次调用都要单独确认。

入口有两个：在 Agent 展开 **高级设置**，选择 **外部工具 MCP**；或者在 **设置 → 功能 → 外部工具 MCP** 中选择 **管理连接**。MCP 需要智能模式，私密文件夹不可使用。

## 添加服务

1. 选择 **添加服务**，填写 **名称** 与 **连接方式**。
2. 本地程序：填写 **本地可执行文件**、**参数，每行一项** 和 **环境变量，每行 KEY=value**。kok 不自动安装依赖，也不运行 `npx`。
3. 远程 HTTP：填写 **远程地址（HTTPS）**，并选择 **认证方式**：**无认证 / 静态令牌**、**OAuth 浏览器回调** 或 **OAuth 设备码**。
4. 勾选 **我信任此程序，并允许它以当前账户权限运行**。保存后，无认证或静态令牌的服务会自动连接；OAuth 方式需要先完成登录。
5. 连接成功后展开 **参数结构**，勾选允许 Agent 使用的工具，再选择 **保存工具授权**；工具定义变化后需要重新连接并审核。

## 审批与安全边界

Agent 提出调用时，确认卡片会显示服务 ID、工具名和完整参数，选择 **执行** 后才发送调用。外部调用不参与 **执行所选**，始终逐项批准。

> [!warning]+ 注意
> MCP 程序以当前 Windows 账户权限运行，可以访问资料库以外的文件和网络；资料范围不约束外部服务，外部操作也不能自动撤销。只连接你信任的服务，并逐项核对参数。

本地程序可以勾选 **本地程序使用 AppContainer 沙箱**，并填写 **便携运行时目录（可选）**。沙箱需要用户可写目录中的便携运行时；系统安装目录可能无法授权，此时会明确报错，而不会静默关闭沙箱。

## 连接与配置的边界

配置在本机加密保存，环境变量不会在界面和模型清单中显示。重启 kok 后不会自动启动 MCP 服务，需要手动 **连接**；切换纯净模式、进入私密文件夹、停用相关模块或退出会断开连接。最多配置 12 个服务、每个服务 64 个工具；参数结构不受支持的工具无法授权。
